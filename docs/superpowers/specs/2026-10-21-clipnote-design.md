# ClipNote 剪贴板窗口设计

- 日期：2026-10-21
- 状态：待用户审核
- 工作名称：ClipNote（可随时更名）
- 目标平台：Windows 10/11 x64
- 技术栈：Go 1.26、Windigo 0.2.7、Win32 API

## 1. 目标

实现一个小巧的 Windows 常驻剪贴板工具：

1. 启动后驻留在系统托盘。
2. 每次左键点击托盘图标，捕获点击当下的文本或图片，并新建一个独立窗口显示该内容。
3. 同一内容可以重复打开；点击 N 次就创建 N 个窗口和 N 条临时缓存记录。
4. 窗口先完成内容显示，再在后台写入硬盘缓存；缓存不得阻塞窗口打开或后续编辑。
5. 文本窗口可编辑，图片窗口只读。
6. 标题栏依次显示应用图标、标题和紧贴标题的保存图标，最右侧提供关闭图标，不提供窗口菜单栏。
7. 首次保存弹出 Windows 原生“另存为”对话框；保存成功后再次点击保存图标或按 `Ctrl+S` 直接覆盖当前文件。
8. 临时缓存保留 7 天且总量不超过 500 MiB，超出后从最旧记录开始清理。

## 2. 已确认的界面

### 2.1 剪贴板窗口

- 使用原生 Windows 控件和自定义紧凑标题栏。
- 标题栏最左侧是应用图标，随后是窗口标题，保存按钮紧贴标题文本右侧。
- 标题栏最右侧只有关闭图标，不显示最小化、最大化或窗口菜单栏。
- 文本编辑框只在内容超出可视区域时显示对应的横向或纵向滚动条。
- 窗口仍支持拖动、缩放、双击标题栏最大化和 `Alt+F4`。
- 文本窗口使用多行可编辑文本框；图片窗口使用只读缩放预览。
- 底部状态栏显示内容类型、大小或字符数，以及后台缓存状态。
- 多个窗口使用级联方式错开显示，并限制在当前显示器工作区内。

工作尺寸：

- 默认客户区：720 × 520 逻辑像素。
- 最小客户区：420 × 300 逻辑像素。
- 新窗口相对上一个窗口向右下偏移 24 逻辑像素；到达工作区边缘后重新从左上位置开始。

### 2.2 保存交互

- 保存图标和 `Ctrl+S` 使用同一个“保存”命令。
- 当前窗口没有目标文件时，保存命令打开 Windows `IFileSaveDialog`。
- 当前窗口已有目标文件时，保存命令原子覆盖该文件。
- `Ctrl+Shift+S` 或 `Shift+单击保存图标` 始终打开“另存为”。
- 文本默认文件名为 `剪贴板文本_YYYYMMDD_HHMMSS.txt`。
- 图片默认文件名为 `剪贴板图片_YYYYMMDD_HHMMSS.png`。
- 文本保存为 UTF-8，不写 BOM；换行保持为 Windows 编辑器使用的 CRLF。
- 图片保存为 PNG。
- 文本修改后窗口标题增加 `*`。
- 关闭带未保存修改的文本窗口时，提供“保存 / 不保存 / 取消”选择。

### 2.3 托盘交互

- 左键单击托盘图标：捕获当前剪贴板并打开新窗口。
- 右键单击托盘图标：显示上下文菜单。
- 托盘菜单项：
  - `打开当前剪贴板`
  - `打开缓存文件夹`
  - `清空临时缓存`（执行前确认）
  - `退出`
- 托盘提示文字显示 `ClipNote - 点击打开当前剪贴板`。

## 3. 非目标

首版不包含以下能力：

- 不监听所有剪贴板变化，不维护可视剪贴板历史。
- 不在未点击托盘时缓存剪贴板内容。
- 不支持打开任意文本文件，不承诺编辑 2 GiB 文件。
- 不支持富文本、HTML、文件拖放列表或图片标注。
- 不提供云同步、加密缓存或跨设备同步。
- 不提供安装器、开机自启动项或自动更新。

## 4. 架构

采用单进程架构：

- 一个隐藏的控制器窗口负责消息循环、托盘图标、单实例控制和共享服务。
- 每个剪贴板内容对应一个独立的顶层窗口。
- UI 线程调用 `runtime.LockOSThread()`；所有 Win32 窗口和控件只在 UI 线程创建、更新和销毁。
- 缓存写入在单个后台工作协程中顺序执行，通过消息通知 UI 线程更新状态。
- 保存对话框在 UI 线程以 COM STA 方式调用，保证原生 Windows 行为。

Windigo 的高层 `ui` 包没有托盘与任意多顶层窗口的直接封装，因此项目使用 Windigo 的 `win` 和 `x/winsh` 原生绑定，并在内部实现一层薄 Win32 适配：

- 剪贴板读取：`OpenClipboard` / `GetClipboardData` / `CloseClipboard`
- 托盘：`Shell_NotifyIconW`
- 原生窗口和控件：`CreateWindowExW`、标准 `EDIT`、自绘标题栏、原生状态栏
- 保存对话框：`IFileSaveDialog`
- 图片转换：Go 标准库 `image` 和 `image/png`

不引入 CGo，不需要 GCC。

## 5. 模块边界

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| `app` | 启动、单实例、生命周期、服务装配 | 其他内部模块 |
| `clipboard` | 在 Win32 剪贴板打开期间复制出不可变快照 | Win32 剪贴板 API |
| `capture` | 内容类型判定、大小限制、快照模型、捕获 ID | `clipboard` 抽象 |
| `cache` | 异步队列、原子写入、元数据、保留策略、清理 | 文件系统 |
| `save` | 保存状态、默认文件名、原子覆盖、保存对话框适配 | 文件系统、COM |
| `ui/tray` | 托盘图标、菜单和通知 | `x/winsh` |
| `ui/window` | 标题栏、编辑框、图片预览、状态栏、窗口消息 | Win32 UI API |
| `ui/controller` | 将托盘点击、窗口创建和后台任务串起来 | 以上全部 |
| `logging` | JSON Lines 日志、范围 debug、轮转 | 标准库 `log/slog` |

核心接口只在内部使用，避免 UI、剪贴板和文件系统互相直接依赖：

```go
type ClipboardReader interface {
    Read() (Snapshot, error)
}

type CacheSink interface {
    Enqueue(Snapshot)
}

type SavePicker interface {
    Pick(parent HWND, kind Kind, suggestedName string) (string, bool, error)
}
```

## 6. 捕获模型与规则

每个快照包含：

- `CaptureID`：时间戳加随机后缀，例如 `20261021T153012-7f3a`。
- `CapturedAt`：本地时间。
- `Kind`：`text` 或 `image`。
- `Text`：文本快照。
- `DIB`：原始 DIB/DIBV5 字节。
- `Image`：解码后的 Go 图片对象，用于窗口显示。
- `SourceFormat`：`CF_UNICODETEXT`、`CF_DIBV5` 或 `CF_DIB`。

格式选择规则：

1. 优先使用非空 `CF_UNICODETEXT`。
2. 没有可用文本时，依次尝试 `CF_DIBV5`、`CF_DIB`。
3. 两种格式都不可用时，不创建窗口，也不写缓存；托盘气泡提示“当前剪贴板没有可用的文本或图片”。

限制与安全阈值：

- 文本超过 32 MiB（UTF-8 编码后）时不打开窗口，提示内容过大。
- DIB 超过 128 MiB 时不打开窗口，提示图片过大。
- 阈值可通过配置覆盖；默认值的目的是覆盖常见代码、日志和截图，同时避免普通文本框和单次缓存写入明显卡顿。
- 超过限制时显式报错并记录日志，不截断、不静默丢弃。

文本 UTF-16 转 Go 字符串后保持原内容；空字符串或只包含 `NUL` 的内容视为无文本。

## 7. 打开与缓存流程

左键点击托盘后，按以下顺序执行：

1. 控制器在 UI 线程上读取剪贴板，并在剪贴板锁内复制全部字节。
2. 对内容进行分类、限制检查和图片解码，形成不可变快照。
3. 创建窗口，设置标题、内容、初始窗口位置和焦点。
4. 显示窗口并同步完成第一次绘制。
5. 首次绘制完成后，才将快照放入缓存队列。
6. 后台工作协程写入临时目录并原子提交。
7. 缓存成功后，通过 UI 消息把状态栏更新为“已缓存”。

由此保证：

- 缓存写入不参与窗口创建和第一次显示。
- 用户可以在缓存完成前立刻编辑文本或操作窗口。
- 同一内容点击多次时，每次都生成独立快照、窗口和缓存目录，不去重。
- 缓存写入的是点击时捕获的原始快照，不是用户之后编辑过的文本。

剪贴板被其他进程短暂占用时，最多尝试 5 次，间隔分别为 20、40、80、160、320 毫秒。仍失败则显示托盘气泡并记录错误；不创建空窗口。

## 8. 缓存格式与保留策略

默认缓存根目录：

```text
%LOCALAPPDATA%\ClipNote\cache\
```

每次捕获使用独立目录：

```text
<cache-root>/
  20261021T153012-7f3a/
    meta.json
    content.txt       # 文本捕获
    content.png       # 图片捕获
```

`meta.json` 至少包含：

```json
{
  "id": "20261021T153012-7f3a",
  "kind": "text",
  "source_format": "CF_UNICODETEXT",
  "captured_at": "2026-10-21T15:30:12+08:00",
  "bytes": 1248,
  "content_file": "content.txt"
}
```

写入规则：

- 先写入同级 `.partial-*` 目录。
- 文件关闭并刷盘后再重命名为最终目录。
- 失败时删除未提交的临时目录；已完成目录不受影响。
- 启动时清理陈旧 `.partial-*` 目录。
- 缓存文件使用当前用户继承的目录权限，不做额外加密。

保留规则：

- 仅清理缓存根目录内由本程序管理的最终目录。
- 先删除超过 7 天的记录。
- 仍超过 500 MiB 时，再从最旧记录开始删除，直到不超过上限。
- 启动时执行一次；之后每成功提交一条缓存记录再执行一次。
- `清空临时缓存` 只删除缓存目录内容，不删除用户手动保存的文件。

## 9. 保存与窗口状态

每个窗口维护：

- 当前内容类型。
- 当前文本或只读图片。
- 是否已修改（仅文本）。
- 当前保存路径。
- 缓存状态。

保存流程：

1. 如果图片没有可写内容或文本为空，仍允许保存空文本文件。
2. 没有保存路径时调用 `IFileSaveDialog`。
3. 对话框过滤器按内容类型限定为 `.txt` 或 `.png`。
4. 用户取消时不改变脏状态。
5. 写入目标目录中的临时文件，成功后替换目标文件。
6. 保存成功后清除脏标记，并把窗口标题中的 `*` 去掉。
7. 保存失败时显示原生错误消息框；文件未改变，窗口保持脏状态。

标准快捷键：

- `Ctrl+S`：保存。
- `Ctrl+Shift+S`：另存为。
- `Ctrl+W`：关闭当前窗口。
- `Ctrl+A`：在文本编辑框中全选。
- `Alt+F4`：关闭当前窗口；没有窗口时程序继续驻留托盘。

## 10. 托盘、单实例与退出

- 使用命名互斥量保证同一用户会话只运行一个实例。
- 再次启动程序时，不创建第二个托盘图标；已有实例收到通知后打开当前剪贴板。
- 窗口关闭不会退出程序，托盘继续运行。
- 托盘菜单“退出”关闭所有窗口并结束进程。
- 退出时等待当前缓存写入到安全点，最多 3 秒；未完成项删除 `.partial-*`，已完成项保留。

## 11. 日志与诊断

- 默认级别：`info`。
- 通过配置或命令行按范围开启 `debug`，例如 `--debug=clipboard,cache,ui`。
- 格式：JSON Lines，每行包含时间、级别、模块、任务 ID、捕获 ID 和消息。
- 正常日志不记录剪贴板正文或图片内容，只记录类型、字节数、路径和耗时。
- 错误日志记录完整上下文：输入标识、阶段、Win32 错误码、路径、耗时和相关中间值。

日志位置：

1. 程序同目录 `logs/`。
2. 不可写时回退到 `%LOCALAPPDATA%\ClipNote\logs\`。
3. 启动日志记录实际路径。
4. `ClipNote.exe --check` 输出实际日志路径、缓存路径、配置路径和版本。

配置位置和默认值：

```text
%LOCALAPPDATA%\ClipNote\config.json
```

```json
{
  "cache": {
    "max_age_days": 7,
    "max_bytes": 524288000
  },
  "capture": {
    "max_text_bytes": 33554432,
    "max_image_bytes": 134217728
  },
  "ui": {
    "progress_delay_ms": 3000
  },
  "log": {
    "level": "info",
    "debug_scopes": []
  }
}
```

配置缺失时使用以上默认值；配置文件存在但解析失败时，显示原生错误对话框并退出，不静默回退。

轮转：

- 按天和 10 MiB 大小切分。
- 单文件达到 10 MiB 时轮转，最多保留 5 个轮转文件。
- 启动时和按天边界执行清理。

进度：

- 窗口显示和缓存写入分别计时。
- 缓存写入超过 3 秒后，状态栏才显示“正在写入缓存…”和“取消”操作；完成、失败或取消后立即替换。
- 缓存取消在文件块边界生效，并删除本次未提交的 `.partial-*` 目录。
- 保存超过 3 秒后显示状态栏进度和“取消”操作；取消后不提交目标文件。
- 3 秒阈值可通过配置覆盖。

## 12. 错误处理

- 失败发生点记录一次完整日志，并返回带上下文的错误。
- 中间层只附加阶段信息，不重复记录日志。
- UI 边界负责把错误转换为气泡、状态栏或消息框。
- 剪贴板读取失败：不创建窗口。
- 图片解码失败：不创建窗口，提示无法显示图片。
- 缓存失败：窗口继续可用，状态栏显示“缓存失败，详见日志”。
- 保存失败：保留当前窗口和未保存状态。
- 缓存清理失败：记录日志并继续运行，不影响新建窗口。
- 未知错误不静默吞掉；没有安全的恢复动作时，由最外层报告给用户。

## 14. 验收标准

- 应用常驻系统托盘，关闭所有剪贴板窗口后仍不退出。
- 每次托盘左键点击都捕获点击当下的内容，并创建独立窗口。
- 窗口先显示内容，缓存写入不阻塞 UI。
- 文本可编辑，图片只读；标题栏仅包含应用图标、标题、紧贴标题的保存图标和右侧关闭图标。
- 保存使用 Windows 原生另存为对话框，并符合首次另存为、后续覆盖的行为。
- 临时缓存满足 7 天和 500 MiB 限制，且不会删除手动保存的文件。
- 日志默认 info，可按范围启用 debug，并能正确轮转和回退路径。
- 不使用 CGo，目标 Windows 环境可直接构建。
