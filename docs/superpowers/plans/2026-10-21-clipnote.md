# ClipNote 剪贴板窗口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. This project explicitly requires inline execution; do not dispatch subagents. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建一个常驻 Windows 托盘的 Go 应用，每次点击托盘创建独立文本或图片窗口，先显示内容，再异步缓存和手动保存。

**Architecture:** 单进程、单 UI 线程。隐藏控制器窗口持有托盘和后台缓存队列；每次点击创建独立原生 Win32 文档窗口。Windigo 的 `win` / `x/winsh` 负责 Win32/COM 绑定，缓存、保存状态、DIB 解码和日志等逻辑放在可独立测试的纯 Go 模块中。

**Tech Stack:** Go 1.26, Windigo v0.2.7, Win32 API, `log/slog`, `image/png`.

## Global Constraints

- 目标平台仅 Windows 10/11 x64。
- 不使用 CGo；必须能在无 GCC 环境构建。
- 窗口没有菜单栏；标题栏最左侧是保存图标，最右侧是关闭图标。
- 首次保存打开 Windows 原生 `IFileSaveDialog`；保存过的文档再次保存时覆盖当前文件。
- 文本窗口可编辑，图片窗口只读。
- 每次点击托盘都产生独立窗口和独立缓存记录，不去重。
- 窗口完成第一次绘制后才允许启动缓存写入。
- 只缓存点击时捕获的内容，不监听全局剪贴板变化。
- 缓存保留 7 天且最多 500 MiB，按最旧优先清理。
- 日志默认 `info`，支持按范围打开 `debug`，JSON Lines，按天和 10 MiB 轮转，保留 5 个文件。
- 日志不得记录剪贴板正文或图片内容。
- 长操作超过 3 秒才显示进度，进度必须提供安全点取消。
- 不推送远端；只做本地提交。

```go
type Config struct {
	Cache   CacheConfig   `json:"cache"`
	Capture CaptureConfig `json:"capture"`
	UI      UIConfig      `json:"ui"`
	Log     LogConfig     `json:"log"`
}

func Default() Config {
	return Config{
		Cache: CacheConfig{MaxAgeDays: 7, MaxBytes: 500 * 1024 * 1024},
		Capture: CaptureConfig{
			MaxTextBytes: 32 * 1024 * 1024,
			MaxImageBytes: 128 * 1024 * 1024,
		},
		UI:  UIConfig{ProgressDelayMS: 3000},
		Log: LogConfig{Level: "info", DebugScopes: []string{}},
	}
}

func Load(path string) (Config, error) {
	cfg := Default()
	data, err := os.ReadFile(path)
	if errors.Is(err, os.ErrNotExist) {
		return cfg, nil
	}
	if err != nil {
		return Config{}, fmt.Errorf("read config %q: %w", path, err)
	}
	dec := json.NewDecoder(bytes.NewReader(data))
	dec.DisallowUnknownFields()
	if err := dec.Decode(&cfg); err != nil {
		return Config{}, fmt.Errorf("decode config %q: %w", path, err)
	}
	if err := cfg.Validate(); err != nil {
		return Config{}, fmt.Errorf("validate config %q: %w", path, err)
	}
	return cfg, nil
}
```

```go
type Paths struct {

func ResolvePaths(exeDir, localAppData string, canWrite func(string) bool) (Paths, error) {
	if exeDir == "" || localAppData == "" || canWrite == nil {
		return Paths{}, errors.New("resolve paths: empty path or nil probe")
	}
	logDir := filepath.Join(exeDir, "logs")
	if !canWrite(logDir) {
		logDir = filepath.Join(localAppData, "ClipNote", "logs")
	}
	return Paths{
		ConfigFile: filepath.Join(localAppData, "ClipNote", "config.json"),
		CacheDir:   filepath.Join(localAppData, "ClipNote", "cache"),
		LogDir:     logDir,
	}, nil
}
```

- [ ] **Step 3: Implement scoped JSON logger**

```go
type Factory struct {
	writer       io.Writer
	defaultLevel slog.Level
	debug        map[string]bool
}

func NewWithWriter(w io.Writer, level slog.Level, scopes map[string]bool) *Factory {
	return &Factory{
		writer:       w,
		defaultLevel: level,
		debug:        maps.Clone(scopes),
	}
}

func (f *Factory) Scope(scope string) *slog.Logger {
	level := f.defaultLevel
	if f.debug[scope] {
		level = slog.LevelDebug
	}
	h := slog.NewJSONHandler(f.writer, &slog.HandlerOptions{
		Level: level,
		ReplaceAttr: func(_ []string, a slog.Attr) slog.Attr {
			if a.Key == slog.TimeKey {
				return slog.String("time", a.Value.Time().Format(time.RFC3339Nano))
			}
			return a
		},
	})
	return slog.New(h).With("scope", scope)
}
```

This creates a new handler per scope, so a debug-enabled scope can emit debug lines while all other scopes remain at the configured default level.
